参考工程：`D:\Weifu\Project\CR\BYD_RL\xxx`

目的：把第一阶段“需求清晰与架构设计”需要明确的内容，按 BYD 量产工程逐项展开。该文档可直接作为和东软沟通、评审、报价、拆计划、定义阶段2交付范围的输入。

## 1. 阶段1总体目标

阶段1不是简单收集需求，而是要把新项目的软件架构冻结到可以指导开发的程度。基于BYD量产工程，阶段1至少要完成以下事情：

1. 明确 ASW、BSW、MCAL、CDD、Boot、HSM、mmWave/RF 各层模块。
2. 明确哪些沿用BYD量产工程架构，哪些因为 NeuSAR/AWR2944LC 需要重新设计。
3. 明确运行时架构：OS Task、ISR、中断优先级、调度周期、任务间触发关系。
4. 明确接口架构：RTE接口、项目级接口、直接BSW API调用、mmWave/IPC/eDMA接口。
5. 明确 Memory Map：Boot、APP、HSM、NvM、共享内存、L2/L3、IPC、标定/数据区。
6. 明确 Boot 架构：BootManager、PlatformBoot、CustomerBoot、APP跳Boot、Boot跳APP、刷写闭环。
7. 明确阶段2必须交付的“mmWave/RF主链路基础平台”，以及阶段3再补齐的OEM/量产功能。

一句话：阶段1结束后，我方和东软必须能回答“系统怎么分层、任务怎么跑、接口怎么接、内存怎么分、Boot怎么刷、阶段2到底交什么”。

### 3.2 BYD工程mmWave运行链路

BYD `rte\OsTask_MMW.c` 中体现了关键运行链路：

  -> 读取 gIpcSharedMem_r5f
  -> RE_ASWIN_InCalc_Copy / Capture
  -> ActivateTask(OsTask_Trigger66ms)

  -> DPM相关处理

1. IPC/Mailbox回调可用。

3. eDMA中断和任务触发可用。
4. mmWave控制任务、DPM任务、触发任务可调度。
5. ASW输出任务能接入CAN调试输出。

## 4. 4.2.3 接口架构

### 4.1 BYD工程接口共存方式

BYD工程不是纯RTE接口，也不是纯手写接口，而是三类接口共存：

```text
RTE生成接口
  Rte.c / Rte.h / Rte_ASW_*.h / SchM_*.h

项目级接口
  OsTask_MMW.c
  AswIf / AswIfSchedule / AswPerception
  net_Scheduler / net_Mngmt

直接BSW API调用
  Com_SendSignal
  NvM_WriteBlock
  NvM_GetErrorStatus
  Dem_SetEventStatus
  ComM_RequestComMode
  CanNm_GetState
```

典型链路：

```text
OsTask_ASW_10ms
  -> RE_COM_SWC_func()
  -> SWC_Com.c
  -> ComPlatform_mainfunction()
  -> net_Scheduler / net_NM_schedule / ComUser_mainfunction
```

另一个典型链路：

```text
Mailbox ISR/Callback
  -> Cdd_Ipc / Mailbox_readCallback
  -> 共享内存解析
  -> 激活或调用ASW/信号处理逻辑
```

### 4.2 新项目接口分类

阶段1必须把接口分成以下几类：

| 接口类别 | 走法 | 代表接口 | 阶段策略 |
|---|---|---|---|
| 标准RTE服务接口 | 通过RTE/SchM | Com、NvM、WdgM、Dem、Dcm、ComM | 阶段2生成骨架，阶段3完整。 |
| ASW Runnable接口 | RTE调度 | ASW_COM、ASW_CORE、ASW_NVM、ASW_WDG | 阶段2必须可编译运行。 |
| 项目级任务适配接口 | C接口/OS Task/Callback | mmWave、IPC、eDMA、DPM、感知输出 | 阶段2必须，不能等阶段3。 |
| CDD接口 | CDD API | TCAN、PMIC、Wdg、Trap、IPC、Flash | 阶段2基础，阶段3完整。 |
| 直接BSW API | 受控允许 | `Com_SendSignal`、`NvM_*`、`Dem_*`、`CanNm_*` | 阶段1列清单，阶段2允许必要项，阶段3规范化。 |

## 5. 4.2.4 Memory Map架构

### 5.1 BYD工程Memory Map事实

BYD linker `TPR12_MCU_LS.lds` 中有关键内存设计：

| 区域 | 地址/大小 | 用途 |
|---|---|---|
| `MSS_L1_TCMA_IVT` | `0x00000004`，约512B | 异常向量。 |
| `MSS_L1_TCMA` | `0x00000200`，约44K | 快速代码/数据、OS/启动相关。 |
| `MSS_L1_TCMA_STACK` | `0x0000B000`，20K | 栈。 |
| `MSS_L1_TCMB` | `0x00080000`，64K | 快速数据/代码。 |
| `MSS_L2_BOOT_RESERVE` | `0x10200000`，128K | Boot Manager保留。 |
| `MSS_L2_APP_DATA_P1` | Boot后384K-32 | APP代码/数据。 |
| `MSS_L2_APP_DATA_P2` | `0x10280000`，384K-256 | APP代码/数据继续。 |
| `MSS_L2_SHARED_RAM` | `0x102dff00`，256B | Boot Manager和APP共享数据。 |
| `MSS_L2_M4_RESERVE` | `0x102E4000`，48K | M4保留。 |
| `DSS_L3_DATA_ONLY_ONCE` | `0x88000000`，64K | L3数据。 |
| `DSS_L3_SHARE_RAM` | `0x88180F00`，4K | L3共享内存。 |
| `DSS_L3_VELOCITY_AMBIGUITY` | `0x88181F00`，约120K | 信号处理/速度模糊相关heap。 |
| `RTOS_NORTOS_IPC_SHM_MEM` | `0xC5000200`，约7488B | IPC共享内存，`.bss.ipc_vring_mem`。 |

BYD工程还定义了 `MSS_L2_SHARED_RAM` 的共享字段：

| 字段 | offset | 用途 |
|---|---:|---|
| Reserve | 0 | BM写，APP读。 |
| lifecycle | 12 | BM写，APP读。 |
| BM version | 16 | BM写，APP读。 |
| PMIC reg | 32 | BM写，APP读。 |
| BootErrflag | 64 | BM写，APP/FBL读。 |

## 6. 4.2.5 Boot架构

| `08_CustData` | 客户数据区。 |

BYD APP侧也有Boot跳转相关接口：

- `EcuM_GetBootTarget`
- `EcuM_SelectBootTarget`
- `RTE_MODE_DcmEcuReset_JUMPTOBOOTLOADER`
- `RTE_MODE_DcmEcuReset_JUMPTOSYSSUPPLIERBOOTLOADER`

### 6.2 新项目Boot架构建议

阶段1必须把Boot拆成两个层级：

**阶段2最小Boot刷写闭环：**

```text
Boot能启动APP
APP能请求进入Boot
CAN/CANFD能刷APP
刷写后APP能启动
刷写失败不启动坏APP
基础CRC/完整性校验
```

**阶段3完整量产Boot：**

```text
BootManager
PlatformBoot
CustomerBoot
UDS完整刷写
HSM/Secure Boot
签名/验签
回滚/防回退
量产包打包
客户数据/威孚数据/标定数据区
ReleaseNote/版本管理
```

### 6.3 阶段1 Boot架构必须明确

| 项目 | 必须明确 |
|---|---|
| Boot范围 | 东软负责完整Boot，还是只负责集成/配置/最小闭环。 |
| Boot分层 | 是否拆BootManager、PlatformBoot、CustomerBoot。 |
| 刷写链路 | CAN还是CANFD，是否UDS on CanTp。 |
| APP跳Boot | Dcm ECUReset、EcuM BootTarget、ResetReason如何实现。 |
| Boot跳APP | APP有效性检查、入口地址、向量表、栈初始化。 |
| 镜像格式 | hex/bin/tiimage/container，镜像头字段。 |
| 完整性校验 | CRC、Hash、签名、HSM验签。 |
| HSM边界 | HSM固件谁提供，CryptoDriver谁负责。 |
| 失败恢复 | 断电、CRC失败、版本不匹配、刷写中断。 |
| 量产包 | 是否参考BYD container_input结构。 |
