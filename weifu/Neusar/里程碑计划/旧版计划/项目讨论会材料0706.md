## 3. 量产工程基线

当前量产工程不是一个简单应用工程，而是完整的 AUTOSAR + 雷达业务工程。新项目需要以这个结构为母版。

| 类别 | 当前量产工程事实 | 对本次合作的要求 |
|---|---|---|
| 顶层工程 | `D:\Weifu\Project\CR\BYD_RL\xxx` | 东软需要理解并映射到该工程形态 |
| COEM | `coem\BYD_UKE` | 新项目需建立类似 `coem\<Project>` |
| 构建 | SCons、`SConstruct`、`scons_gen.bat` | 东软交付需能接入或提供等价自动构建 |
| 工具链 | TI Arm Clang 3.2.2 LTS、Python 3.10、SCons 3.1.0 | 优先沿用，减少工具链风险 |
| 编译目标 | `AM27R_R5_TI` / `AWR2944_R5` | TI 2944LC 支持需东软书面确认 |
| 编译宏 | `AWR2E44P_PLATFORM`、`AUTOSAR_431`、`SUBSYS_MSS`、`SOC_AWR2X44P` | 新项目宏定义需和芯片/SDK 统一 |
| OS | RTA-OS 12.3.0，ARVersion 4.8.0，SC1，400 MHz | NeuSAR OS 需要给出等价配置 |
| BSW | `bswpf\autosar` + `coem\BYD_UKE\gen_bsw` | 东软需交付等价 BSW 配置和生成物 |
| MCAL | `bswpf\mcal` | 东软需给出 TI 2944LC MCAL 支持矩阵 |
| CDD | `bswpf\cdd` | 外设缺口按 CDD 方式管理 |
| 雷达业务 | `mmwave`、`adas`、`asw` | 我方主导，东软配合 OS/RTE/BSW 接口 |

注意事项：

1. `readme.md` 内部仍有 `BAIC_B41VS` 示例，但实际项目目录是 `BYD_UKE`，会议中以真实目录和脚本为准。
2. 当前工程已有 ETH 中断和配置痕迹，但不能默认新项目必须上完整 DoIP/SOMEIP，需按新项目通信需求确认。
3. 当前工程编译宏和 OS summary 中 AUTOSAR 版本存在 `AUTOSAR_431` 与 ARVersion 4.8.0 并存现象，需作为工具链/配置一致性问题澄清。

### 阶段 2：雷达控制链路接入，3-4 周

目标：把当前量产工程中的 `mmwave` 控制面接入 AUTOSAR 任务框架。

东软交付：

1. OS/ISR 配置更新。
2. RTE 或 BSW service 接口。
3. mailbox/EDMA/HWA 相关中断注册说明。

我方交付：

1. `mmwave` 控制代码适配。
2. RF 配置和启动验证。

2. mailbox/EDMA 中断可触发或空回调可验证。
3. 雷达控制链路可执行到 RF 配置或 frame control 阶段。

## 11. 会上可以直接说的核心口径

> 我们不是要东软做一个通用 AUTOSAR Demo，而是要基于我们现有 `CR60 Light` 量产工程形态，交付 TI 2944LC 项目的等价 NeuSAR BSW/MCAL/CDD/RTE/OS 工程。第一阶段先做最小闭环，但这个最小闭环必须贴近量产工程：要有 BSW/ASW 基础任务、CAN、DCM、DEM、NvM、WdgM，以及雷达项目关键的 `MmWaveCtrl`、`DPM`、`TriggerWave`、mailbox/EDMA 空链路。雷达算法和 mmWave 业务由我们主导，东软重点负责 AUTOSAR 平台、配置、驱动适配和集成支持。
